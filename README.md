### 🎨 Vibe Coding 实践：轻律生活 EasyLife

2026 年 9–10 月的**重点投入项目**，也是我目前 vibe coding 的代表案例：**从需求文档到真机上线，整条链路由 AI 驱动，主要精力压在做 UI 界面和动效上。**

**为什么选它做载体**

Vibe coding 最大的风险是「能跑，但不好看」——AI 生成的界面往往功能正确却毫无质感。这个项目刻意选了卡路里记录这个题材：核心痛点是**反馈太抽象**（只知道多了 300 大卡，不知道这相当于什么）。逼着我把精力放在界面反馈与动效上，而不是先堆业务功能。

**界面与动效上的具体投入**

| 投入点 | 做法 |
|--------|------|
| **水瓶液体**（首页核心） | 不是图片，是 **Canvas 2D 实时渲染的物理模拟**：双模强迫阻尼振荡器（M1：cos(πu)，T=460ms，ζ=0.14；M2：sin(4πu+φ)，0.955 衰减，dt 归一化）、34 段表面路径 + 气泡池 8 + 粒子池 12。点击瓶身注入扰动，晃动两下后归于平静；**首次进入不晃动**，安静开场 |
| **主题系统** | 三主题（薄荷 / 海洋 / 薰衣草）× 亮暗 = **6 档token 矩阵、20 个角色 token**。关键决策：**放弃 CSS 变量**，改为逐元素行内 `:style` 绑定 —— uni-app x 原生端没有可靠的层叠与 CSS 变量通道 |
| **视觉资产** | 347 条食物图标全部 **AI 生图**，原始 PNG 留档入库（生图不可复现，不留档就补不回来）；UI 走薄荷液滴视觉方向 |
| **超标反馈的克制** | 三档色（绿 / 琥珀 `#E8B54D` / 珊瑚 `#FF9E7D`），**超标不用红色** —— 红色是报错色，珊瑚既有警示感又不劝退 |
| **真机视觉调优** | 设计稿上 15px 的字看着舒服，真机上就是小。靠rpx + px 逐页微调才最终收敛 —— 这个迭代只有真机能暴露 |
| **设备能力分档** | 检测机型/芯片后分 high / mid / low，低档自动关闭触觉反馈、液体波纹、毛玻璃 |

**规模**：8 条路由 / 9 组件 / 6 个 Pinia store / 347 条食物库 / 约 1.2 万行 `.uvue` + `.ts`，纯本地存储无服务器，Android / 微信小程序 / Web H5 三端各自独立运行。

**vibe coding 的工作流与取舍**

```
① PRD 需求文档 → ② DesignTokens（色值/字号/圆角唯一事实来源）→ ③ HTML 可点击原型
→ ④ AI 生图做高保真视觉稿 → ⑤ 代码实现 → ⑥ 真机验收 → ⑦ rpx/px 逐页视觉微调
```

- **设计先行**：`design/DesignTokens.md` 是色值、字号、圆角的唯一事实来源，代码里任何颜色都要能对应到它 —— 避免页面之间慢慢长成两套设计系统。
- **文档即上下文**：`docs/decisions/` 五份 ADR + uni-app x 踩坑实录。因为原生端有一批「Web 上能写、原生上静默失效」的坑，值得被记住。
- **AI 的边界在哪**：AI 能快速产出可用界面，但「质感」必须自己一遍遍磨 —— 真机验收和逐页微调这两步没法外包给 AI。
